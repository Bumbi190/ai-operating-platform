# Chapter 22 — Execution Evidence, Learning and Governed Memory

<a id="section-22-1"></a>
## 22.1 Chapter Status

This chapter defines the canonical architecture, object model, lifecycle, boundaries, governance requirements and conformance rules for execution evidence, evaluation evidence, Decision Evidence, Derived Learning and Governed Memory within the Omnira Intelligence Fabric.

It establishes:

- how every meaningful Execution remains reconstructable,

- how evidence differs from logs, telemetry, provenance, Assets and ordinary application data,

- how Execution Records, Attempt Records, Receipts and Evidence Bundles remain distinct,

- how Provider responses, Tool results, human contributions and external state observations become governed evidence,

- how evidence confidence, completeness, freshness, integrity and trust are represented,

- how facts remain distinguishable from claims, observations, interpretations and Decisions,

- how evaluation evidence remains linked to exact Outputs, Assets, Models, Providers and Deployments,

- how Decision Evidence explains why Omnira selected, approved, rejected, retried, stopped or escalated an action,

- how Derived Learning is formed from evidence without becoming unquestioned truth,

- how learning remains scoped to the correct Tenant, Project, Capability, resource and time period,

- how confidence, validity, expiry, challenge and replacement are preserved,

- how Governed Memory differs from raw chat history, logs, vector indexes and arbitrary stored context,

- how Memory admission requires purpose, authority, classification, provenance and retention,

- how Atlas and other Agents retrieve Memory without receiving unrestricted historical data,

- how Agent identity and Memory remain independent from the Model currently serving the Agent,

- how working memory, episodic memory, semantic memory, procedural memory and policy memory remain distinct,

- how Project Memory remains isolated from Personal, Tenant and Platform Memory,

- how private, confidential and Local Only evidence remains protected,

- how consent, rights and retention limit memory use,

- how incorrect or outdated Memory is challenged, corrected, superseded, expired or deleted,

- how contradictory evidence remains visible rather than overwritten silently,

- how Memory retrieval preserves source citations and confidence,

- how Derived Learning influences Routing, Planning, Quality, Reliability and Cost without bypassing policy,

- how feedback and outcomes are converted into evaluation rather than raw reinforcement,

- how Model-generated summaries are prevented from becoming canonical fact automatically,

- how human knowledge remains attributable,

- how system self-observation remains bounded,

- how event streams, audit records, Metrics and traces support but do not replace governed evidence,

- how evidence and Memory survive provider, Model and infrastructure changes,

- how incidents involving corrupted evidence, false Memory, leakage or unauthorised learning are contained,

- and how Stage 1 shall implement the smallest trustworthy evidence, learning and Memory foundation.

A log is not automatically evidence.

Evidence is not automatically fact.

A Provider response is not automatically true.

An accepted Output is not automatically permanent Memory.

Provenance is not evaluation.

Evaluation is not Decision Evidence.

Decision Evidence is not Derived Learning.

Derived Learning is not Governed Memory.

Governed Memory is not a raw transcript archive.

A vector embedding is not Memory authority.

A high confidence score is not certainty.

Repeated occurrence is not proof of universality.

An Agent’s statement is not canonical truth merely because the Agent produced it.

A human correction shall not disappear behind a later Model summary.

A newer Memory item does not automatically invalidate an older one without scope and evidence.

Deletion from an index does not prove deletion from every evidence store.

This chapter is normative after formal approval.

Data classification, privacy and isolation are expanded in Chapter 23.

Approval, authority and bounded autonomy are expanded in Chapter 24.

Observability, audit and Incident Response are expanded in Chapter 25.

Implementation and operational conformance must be verified separately.

<a id="section-22-2"></a>
## 22.2 Purpose of Evidence, Learning and Memory Governance

The Intelligence Fabric performs work through:

- Agents,

- Models,

- Providers,

- Tools,

- Adapters,

- Connectors,

- local Nodes,

- human operators,

- scheduled workflows,

- external services,

- and publication systems.

Those systems produce:

- requests,

- Plans,

- Attempts,

- Outputs,

- provider-job states,

- Costs,

- Quality results,

- approvals,

- incidents,

- external side effects,

- user feedback,

- and business outcomes.

Without canonical evidence governance, Omnira could:

- forget why a Provider was selected,

- retry a paid job whose outcome is unknown,

- treat a generated answer as verified fact,

- learn from a failed or rejected Output,

- propagate one Project’s preference into another Project,

- preserve outdated information indefinitely,

- expose private transcripts through Agent context,

- lose links between a Memory claim and its sources,

- overwrite contradictory evidence,

- or allow one Model’s summary to become permanent system truth.

The architecture exists to ensure that Omnira can answer:

- What happened?

- What was intended?

- Which Plan and policy applied?

- Which resource executed the work?

- What did the Provider or Tool return?

- Which external state was verified?

- What did the human approve or reject?

- Which evidence supported the Decision?

- What was learned?

- How confident is that learning?

- Which scope does it apply to?

- When does it expire?

- Who may retrieve it?

- How can it be challenged or replaced?

- What remains unknown?

<a id="section-22-3"></a>
## 22.3 Evidence

Evidence is a governed record or artefact that supports reconstruction, verification, evaluation or explanation of a claim, event, state, Decision or outcome.

Evidence may be:

- direct,

- indirect,

- machine-generated,

- human-generated,

- Provider-generated,

- externally verified,

- inferred,

- or disputed.

<a id="section-22-4"></a>
## 22.4 Evidence Is Not Truth

Evidence supports a conclusion.

It does not guarantee that the conclusion is correct.

<a id="section-22-5"></a>
## 22.5 Evidence Is Not Log Data

Logs may provide evidence.

Ordinary debug or operational log entries do not become canonical evidence automatically.

<a id="section-22-6"></a>
## 22.6 Evidence Is Not Provenance Alone

Provenance explains origin and transformation lineage.

Evidence may additionally support:

- quality,

- external state,

- authority,

- cost,

- or Decision reasoning.

<a id="section-22-7"></a>
## 22.7 Evidence Is Not Memory

Evidence may be retained without being admitted into Agent-accessible Memory.

<a id="section-22-8"></a>
## 22.8 Evidence Is Not Learning

Learning is a derived and governed interpretation of evidence.

<a id="section-22-9"></a>
## 22.9 Learning Is Not Automatic

The existence of repeated evidence does not authorise automatic creation of a permanent rule.

<a id="section-22-10"></a>
## 22.10 Governed Memory

Governed Memory is an authorised, scoped, attributable, classified, reviewable and lifecycle-controlled representation of knowledge, preference, procedure, context or historical fact intended for future retrieval.

Governed Memory shall remain linked to evidence or an authorised human source.

<a id="section-22-11"></a>
## 22.11 Memory Is Not Transcript Storage

A transcript archive may support audit or reconstruction.

It shall not become the canonical Memory layer by default.

<a id="section-22-12"></a>
## 22.12 Memory Is Not Prompt Context

Prompt context is the bounded data supplied to one Model invocation.

It may include retrieved Memory.

It is not itself durable Memory.

<a id="section-22-13"></a>
## 22.13 Memory Is Not Vector Storage

A vector store may index Memory or evidence.

The vector store does not define canonical truth, ownership or authority.

<a id="section-22-14"></a>
## 22.14 Memory Is Not Agent Identity

Agent identity remains stable even when its Memory changes.

Memory remains independently governed.

<a id="section-22-20"></a>
## 22.20 Direct Evidence

Direct Evidence originates from the system or event being observed.

Examples include:

- Provider job status,

- external publication ID,

- signed response,

- file checksum,

- or human approval record.

<a id="section-22-21"></a>
## 22.21 Indirect Evidence

Indirect Evidence supports a conclusion through interpretation or correlation.

Examples include:

- inferred Provider outage,

- likely duplicate publication,

- or estimated user preference.

<a id="section-22-22"></a>
## 22.22 Primary Evidence

Primary Evidence is the most direct authoritative source available for the claim.

<a id="section-22-23"></a>
## 22.23 Secondary Evidence

Secondary Evidence reports or interprets another source.

<a id="section-22-24"></a>
## 22.24 Corroborating Evidence

Corroborating Evidence independently supports the same claim.

<a id="section-22-25"></a>
## 22.25 Contradictory Evidence

Contradictory Evidence conflicts with another Evidence Item.

It shall remain visible and linked.

<a id="section-22-26"></a>
## 22.26 Negative Evidence

Negative Evidence records the absence of an expected result or signal.

Absence shall not be interpreted beyond what the observation can prove.

<a id="section-22-27"></a>
## 22.27 Human Evidence

- approval,

- rejection,

- correction,

- attestation,

## 22.28 Machine Evidence

Machine Evidence may include:

- API response,

- Tool Output,

- checksum,

- Metric,

- trace,

- or structured validation result.

<a id="section-22-29"></a>
## 22.29 Provider Evidence

Provider Evidence originates from an external Provider.

- Account identity,

- timestamp,

- response integrity,

- and possible inconsistency.

## 22.30 Model-Generated Evidence

Model-generated text may describe or classify evidence.

- post published,

- file exists,

- invoice issued,

- job completed,

- email sent,

- or repository commit present.

## 22.42 Claim Status

- proposed,

- supported,

- strongly supported,

- verified,

- contradicted,

- disputed,

- unresolved,

- expired,

- and superseded.

<a id="section-22-43"></a>
## 22.43 Verified Claim

Verified means the claim satisfies the defined verification policy for its scope.

It does not mean universal certainty.

<a id="section-22-44"></a>
## 22.44 Unresolved Claim

Required evidence remains incomplete or conflicting.

<a id="section-22-45"></a>
## 22.45 Disputed Claim

Material evidence or authorised human Decisions conflict.

<a id="section-22-46"></a>
## 22.46 Evidence Confidence

Confidence estimates how strongly the available evidence supports a claim.

It shall preserve:

- method,

- scale,

- source quality,

- evidence count,

- contradictions,

- and uncertainty.

<a id="section-22-47"></a>
## 22.47 Confidence Scale

A canonical confidence scale may include:

- unknown,

- very low,

- low,

- moderate,

- high,

- very high,

- and verified under defined policy.

<a id="section-22-48"></a>
## 22.48 Confidence Is Not Probability Automatically

A confidence label shall not be represented as a precise probability unless the method supports that interpretation.

<a id="section-22-49"></a>
## 22.49 Evidence Freshness

Freshness indicates how current the Evidence Item is relative to the claim.

## 22.658 Closing Statement

Execution Evidence, Learning and Governed Memory allow Omnira to improve without losing accountability.

Evidence records what was observed.

The Execution Record preserves what was attempted.

The Attempt Record preserves which resource performed the work.

The Provider Response Record preserves what the external service reported.

The Tool Result Record preserves what local or connected Tools returned.

The Human Action Record preserves what people approved, rejected or corrected.

Outcome Verification determines whether the intended external or business state actually occurred.

The Evaluation Record determines how well the result satisfied defined criteria.

Decision Evidence explains why Omnira selected, approved, retried, rejected, stopped or escalated.

Derived Learning turns repeated, reviewed evidence into bounded conclusions.

The Memory Admission Decision determines what may be retained for future use.

The Memory Item preserves that retained knowledge with sources, scope, confidence, validity and expiry.

The Memory Retrieval Record explains what context influenced an Agent or Decision.

The Memory Challenge ensures that wrong or outdated knowledge can be corrected.

The Memory Supersession preserves history without allowing stale truth to govern the present.

For Familje-Stunden, this architecture ensures that:

- Nova and Pling continuity learning remains Project-scoped,

- child-facing safety rules remain sourced and reviewable,

- rejected illustrations can improve future selection without becoming canonical references,

- and private family material never becomes general Memory automatically.

For The Prompt, it ensures that:

- source reliability patterns remain time- and source-scoped,

- generated visuals remain distinct from documentary evidence,

- publication completion is externally verified,

- and one successful news format does not become an unquestioned universal template.

For GainPilot, it ensures that:

- Arnold remembers the current programme,

- programme age and change history remain explicit,

- user goals and constraints remain sourced,

- and coaching improvements arise from verified outcomes rather than repeated assumptions.

For Atlas, it ensures that:

- platform doctrine remains available across Model changes,

- Project context remains isolated,

- user preferences remain bounded,

- operational state expires when stale,

- and Memory never replaces current authority, policy or evidence.

For Omnira, it ensures that:

- Agents,

- Models,

- Providers,

- local Nodes,

- Tools,

- humans,

- workflows,

- Assets,

- Decisions,

- Incidents,

- and outcomes

contribute to one governed body of evidence without collapsing into one uncontrolled data archive.

The Provider may change.

The Agent may continue.

The user may correct the system.

The Project may evolve.

The evidence must remain.

The Memory must remain challengeable.

No Evaluation without an exact target.

No Decision without material evidence.

No Learning without sources.

No Memory without admission.

No Memory retrieval without scope.

No confidence without uncertainty.

No Agent identity tied to one Model.
