# Growth Engine — proposed 14-day The Prompt pilot

Status: local protocol only. No start date, account access, budget, experiment, schedule, capture or publication is authorized by this document.

## Entry conditions

- Review and merge the exact source commit through the existing required CI checks. Complete any unresolved broad regression and security gates.
- Build an approved trusted evidence reader and project/account binding. The current admission intentionally returns projection:null and authorizesPilot:false. The current capture factory is disabled; the dashboard component is not mounted in production.
- Obtain an explicit owner decision naming The Prompt (slug ai-media-automation), the account, permitted read/capture operations, retention, a monetary ceiling and stop conditions. An existing platform AI budget is not automatically a pilot budget.
- If persistence needs the preserved SQL foundation, independently review its public.projects triggers and existing-table ACL effects. Verify the target catalog, effective permissions, Data API exposure, exact migration source and ledger coordination before a separately approved migration.

## Measurement protocol

The initial goal is trustworthy observations and useful advice, not a promised growth percentage. Use existing approved publishing unchanged. Do not create automatic experiments or publish advice. Keep Familje-Stunden, The Prompt and every account separate.

Before the first eligible post, fix the observation age and allowed timing tolerance, eligible content types, outcomes, denominators, deduplication key, minimum sample and missing-data rules. Record publication and observation times in UTC from trusted per-post evidence. A mutable latest-cache fetched_at timestamp does not reconstruct a historical fixed-age observation.

Treat unavailable figures as unknown, preserve real zeroes, deduplicate per project/account/post/window, and reject mixed scopes. Keep reach, views, followers, leads and paying customers distinct. Quality scores describe the rubric and its source support; they do not estimate viral probability.

## Proposed sequence

| Period | Work | Review evidence |
| --- | --- | --- |
| Before day 1 | Freeze scope, timing rules, permitted data access, budget and baseline definition | Owner decision and exact source/reader identity |
| Days 1–3 | Check eligible publication receipts and fixed-age capture completeness | Scope, timestamps, missing values, duplicate rejection and no unauthorized effects |
| Days 4–7 | Review the four advisory sections using the same rules | Traceable observations, verified reference features, explainable rubric and uncertainty |
| Days 8–13 | Continue comparable observations; propose manual changes only | Advice remains separate from publication authority; no silent threshold changes |
| Day 14 | Close the observation window and review | Completeness, reproducibility, costs, errors, limits and a separate continue/stop decision |

A 14-day sample may be too small to infer causal uplift or select a statistical winner. Do not label a descriptive A/B difference as significant without an appropriate predeclared design, adequate sample and uncertainty assessment.

## Stop and close

Stop new capture on revoked/blocked binding, scope mismatch, uncertain post provenance, unexpected writes, exceeded approved budget or a security incident. Preserve the audit trail without exposing credentials. Ordinary already-approved publishing is governed independently; this protocol grants no authority to alter it.

Close with observed counts, missing/duplicate/denied counts, attributable costs, reproducible advice and limitations. Starting another period, changing thresholds, activating capture, mounting a live dashboard or changing publishing requires the applicable separate decision.
