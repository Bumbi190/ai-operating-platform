# Atlas Live Build Workspace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. Preserve André's previously selected Native method: implement here, then obtain one independent whole-branch review.

**Goal:** Atlas bygger en riktig statisk webbplats från en brief, visar den i Omnira och tar emot versionsbunden text- och röstfeedback under arbetet.

**Architecture:** En projektbunden BuildSession lagrar brief, feedback och oföränderliga PreviewRevision-artifacts. Ett deklarerat website-run använder Omniras befintliga drainer, claims, stoppar och kostnadsgrind; chatten väntar inte på bygganropet. Arbetsvyn visar senaste godkända artifact i en isolerad iframe och hämtar status var tredje sekund.

**Tech Stack:** Befintliga Next.js 14.2.29, React 18, TypeScript, Supabase/Postgres, Vitest och JSZip. Lägg endast till exakt pinnade `parse5@7.3.0` för serverns HTML-parsning och `@playwright/test@1.64.0` för riktiga browsertester; uppdatera rotens lockfil. Paketversionerna verifierades via npm-registret 2026-10-14; inga Supabase-paketuppgraderingar ingår.

**Spec:** `docs/superpowers/specs/2026-10-14-atlas-live-build-workspace.md` (godkänd av André 2026-10-14).

## Global Constraints

- "Börja med riktiga statiska webbplatser i HTML/CSS/JavaScript, utan krav på npm-installation för varje genererad sida."
- "Den första leveransen ska kunna skapa flera sidor, mobilmeny, grundläggande interaktioner, riktiga texter och ett exportbart sidpaket från en brief."
- "Visa senaste fungerande version medan nästa byggs."
- "En stängd mikrofon eller avbruten uppläsning stoppar inte bygget."
- "Feedback får inte försvinna vid reload, reconnect, retry eller återupptagen worker."
- "Dubbelsändning med samma idempotency key får bara skapa ett meddelande."
- "En session har högst en arbetande writer med lease/fence, så en gammal worker inte kan publicera en revision efter avbrott eller ny claim."
- "Initialt räcker polling var tredje sekund för sessionstatus, nya revisioner och feedbackkvittens."
- "Publik deployment är en separat åtgärd med verifierad URL och livekontroll."
- PR #331/#332 måste integreras och migration guard passera före aktivering i produktion. Ingen kringgång av guard, hosted CI-körning eller ändring i den smutsiga originalcheckouten.

## Review Focus

1. Feedback och revisioner anländer i fel ordning efter reconnect: UI ska följa serverns monotona sekvens och behålla utkast.
2. Cancel/paus, claimbyte och artifactcommit konkurrerar: endast aktuell writer får aktivera en version; paus får kvittens först vid observerad stegräns.
3. Genererad markup försöker exekvera kod eller ladda ett annat projekt: avvisa artifacten och behåll senaste fungerande preview.
4. Tal slutar efter routebyte, eller webbläsaren saknar STT: ingen instruktion får skickas till fel session; text ska alltid fungera.
5. Långa svenska texter, å/ä/ö, liten mobil och 200 % textstorlek: meddelanden, kontroller och export ska vara läsbara och korrekta.

Den första adaptern tar fram fri HTML/CSS och **deklarativa beteenden**, inte exekverbar modellskriven JavaScript. En liten granskningsbar runtime skapar riktig JavaScript för meny, flikar, accordion och intern sidnavigering. Det uppfyller första leveransens interaktioner och export, utan att ge genererad kod nätverks- eller navigeringsrättigheter. Backendfunktioner markeras som integrationsbehov; visuell formulärlayout får ingen falsk "skickat"-kvittens.

Definiera följande i `lib/website-build/types.ts` och använd samma namn överallt:

```ts
type FeedbackStatus = 'received' | 'acknowledged' | 'applied' | 'rejected' | 'superseded'
type BuildStatus = 'queued' | 'interpreting' | 'building' | 'validating' | 'ready' | 'awaiting_decision' | 'pausing' | 'paused' | 'cancelling' | 'cancelled' | 'failed'
type WebsiteBehavior = { kind: 'toggle' | 'tabs' | 'accordion'; triggerId: string; targetIds: string[] }
type WebsiteDraft = { format: 'static-website.v1'; title: string; pages: { key: string; title: string; bodyHtml: string; css: string; behaviors: WebsiteBehavior[] }[] }
type WebsiteArtifact = { format: 'static-website.v1'; sha256: string; pages: { key: string; title: string; html: string }[]; files: { path: string; content: string }[]; integrationNeeds: string[] }
type BuildPrincipal = { userId: string; allowedProjectIds: string[] }
type BuildRef = { projectId: string; sessionId: string }
type WriterRef = BuildRef & { runId: string; claimId: string; generation: number }
type BuildFeedback = { id: string; sequence: number; authorId: string; text: string; inputSource: 'text' | 'voice'; viewedRevisionId: string | null; status: FeedbackStatus; interpretation: string | null; appliedRevisionId: string | null; createdAt: string }
type PreviewRevision = { id: string; number: number; generation: number; feedbackSequence: number; sha256: string; createdAt: string; pages: { key: string; title: string }[] }
type BuildSessionView = BuildRef & { stateVersion: number; conversationId: string; status: BuildStatus; stage: string; agentId: string; activePreviewRevisionId: string | null; controlRequested: 'pause' | 'cancel' | null; updatedAt: string; revisions: PreviewRevision[]; feedback: BuildFeedback[] }
type CreateBuildInput = { projectId: string; agentId: string; conversationId: string; brief: string; idempotencyKey: string }
type FeedbackInput = { idempotencyKey: string; text: string; inputSource: 'text' | 'voice'; viewedRevisionId: string | null }
type FeedbackInterpretation = { items: { feedbackId: string; summary: string; disposition: 'apply' | 'answer' | 'reject' | 'decision'; changeKey: string | null; supersedesFeedbackIds: string[] }[] }
type BuildSnapshot = { writer: WriterRef; brief: string; agentId: string; previousArtifact: WebsiteArtifact | null; feedback: BuildFeedback[]; candidate: WebsiteArtifact | null }
```

Övriga input/result-typer deklareras av uppgiften som producerar dem. Serialisering använder UTF-8, normaliserad objektordning för hash och serverns tidsstämplar. Innehållsgränser: 8 sidor, sammanlagt 1 MiB UTF-8 per artifact, 64 beteenden per sida, brief 8 000 tecken, feedback 4 000 tecken. Överskridanden ger explicit valideringsfel, ingen trunkering. Inga externa assets hämtas i första adaptern; tillåt enbart begränsade inbäddade PNG/JPEG/WebP-bilder och inga SVG-/HTML-data-URL:er.

Alla API-funktioner använder `resolveProjectAccess()` och `assertProjectAllowed()` från befintliga `lib/auth/project-access.ts`; ingen ny roll eller projektbehörighet uppfinns. Agent och konversation måste också tillhöra rätt projekt respektive användare. Preview får endast webbplatsens avsedda innehåll, aldrig service-role, sessioncookies eller konversationens kontrollmetadata. Sessionens `stateVersion` ökar atomiskt vid varje synlig övergång; statuspolling jämför detta värde, inte klientens klocka.
