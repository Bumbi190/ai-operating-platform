# Atlas Local Text Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Atlas request a bounded text job, obtain independently reviewed output from the Windows GPU worker, and expose its durable receipt or governed escalation.

**Architecture:** A project-scoped helper policy selects admitted capabilities; a dedicated signed outbound worker protocol delivers fenced jobs to the existing local inference module. Cloud review and one possible fallback use existing run-bound stop/spend boundaries. The main Atlas model profile remains separate.

**Tech Stack:** Next.js 14 / TypeScript / Vitest, Supabase PostgreSQL and local SQL tests, dependency-free Node ESM, Windows PowerShell/CNG, pinned Ollama and NVIDIA.

**Spec:** `docs/superpowers/specs/2026-10-17-atlas-local-text-integration-design.md` (owner approved 2026-10-17, 10:33 Europe/Stockholm). Pilot evidence: `docs/architecture/local-models/2026-10-17-verification.md`.

**Execution:** Preserve André's previously chosen **Native** method: implement in this session after plan review, then obtain independent branch review. The completed pilot is evidence, not an implementation of this integration. This document changes no runtime, database, autostart, production flag or admission.

## Global Constraints

- Keep RTX 3060 12 GB and 16 GB RAM. Do not purchase or upgrade hardware.
- Isolate all work from the dirty primary checkout and other Omnira branches. Never reset/stash their changes, merge or deploy this work implicitly.
- Only `classify`, `extract`, `summarize`; input at most 3000 Unicode code points. No tools, shell, arbitrary URLs, provider/model overrides or material actions in a task.
- `local_assist_v1` is explicitly admitted per project; do not change `ATLAS_MODEL_PROFILE`, voice, studio or code-worker authority.
- First candidates: Qwen3.5 4B classify/extract; Qwen3 8B summarize; Qwen3.5 9B classify only. Exact model/runtime/adapter/prompt/schema/configuration evidence and project admission are required.
- Ollama stays on `127.0.0.1:11434`, cloud disabled, one inference and one loaded GPU model. Preserve runtime lifecycle lease across model switches, unload and GPU probes. No implicit CPU fallback or download/update.
- Local configuration remains `num_ctx=4096`, `num_predict=384`, `temperature=0`, `stream=false`, `think=false`, `keep_alive=2m`; total job inference budget 90 seconds; health deadline 3 seconds; reply limit 128 KiB; stdin/body limit 64 KiB.
- Prove full prompt/context fit before generation, including template, schema and output reserve. Otherwise return `TOKEN_BUDGET_UNVERIFIED` or `INPUT_TOO_LARGE`; never truncate or silently enlarge context. Decode UTF-8 fatally.
- Worker heartbeat 15 seconds; health freshness 45 seconds; one offline incident after 90 seconds. Stop admission immediately on revocation, claim loss, stale health or canonical stop.
- Job expiry and raw source/result/review payload retention: 24 hours from creation, or shorter project policy. Metadata/hashes: maximum 90 days. Expired approval projections contain no recoverable raw copy and cannot authorize execution.
- Only synthetic or owner-approved text permitted in the Atlas cloud control plane and chosen review provider. Unknown classification, secrets, fully-local-only and offline-only requirements are ineligible for this pilot.
- At most one local inference, one cloud task inference and one independent review of each produced result: maximum three cloud calls. No fallback after an uncertain dispatch until reconciliation. Reviewer error/unknown never means approved.
- Every cloud call uses existing `runStep`, canonical run authority and governed project spend. Codex remains unavailable until an actual separate adapter exists. Local API charge zero does not imply zero operating cost or net savings.
- Suggested pilot ceilings, to be explicitly recorded during project admission: USD 0.25 per job and USD 5 per project/day, or stricter existing limits. Reserve all possible calls within those limits; pricing/usage uncertainty blocks automated cloud dispatch. These are caps, not a spend authorization from this document.
- Proposed first startup mechanism: current-user Task Scheduler **AtLogOn**, least privilege, no saved password. This starts after operator login following reboot; it does not promise service before login. No task installation, sleep/autologin/power/credential/firewall change without review of exact setup and rollback. Unattended pre-login service is outside this first mechanism.

## Review Focus

1. Same idempotency key with changed source/project/schema must fail instead of silently returning another request's result (Tasks 1, 3, 9).
2. A disconnected or terminated worker with an uncertain inference cannot free its fence/GPU lock or trigger duplicate cloud work (Tasks 3, 6, 8).
3. Unicode, escaped JSON and template overhead must not defeat the 4096-token context bound; unreadable tokenizer evidence denies dispatch (Task 2).
4. A valid old signature/admission/result must fail after key revocation, expiry or model/prompt drift, including races with completion (Tasks 4, 5, 6).
5. A rejected/replayed review, deleted source or pending approval must not leak raw data or fabricate a fresh successful receipt after reload/retention cleanup (Tasks 7, 9, 10).

Shared types are defined by Task 1 and re-exported by `apps/web/lib/local-text/types.ts`; do not invent rival shapes downstream:

- `Task`: `{kind:'classify',text:string,labels:string[]} | {kind:'extract',text:string} | {kind:'summarize',text:string}`; classification labels are unique, trimmed, 2–8 labels with at most 64 code points each. Results: classify `{label:string}` from allowed labels; extract `{company:string|null,city:string|null,registrationNumber:string|null}` with nonempty strings at most 300 code points; summarize `{bullets:string[]}` with 1–3 nonempty bullets at most 300 code points each. Unknown result properties fail.
- `RequestLocalText`: `{projectId:string,conversationId:string,idempotencyKey:string,task:Task}`; UUIDs strict, unknown properties refused. No tool-controlled privacy or model fields.
- `JobState`: `queued | claimed | running | reviewing | escalation_pending | needs_input | succeeded | failed | cancelled | reconciling`.
- `JobReceipt`: `{id,projectId,conversationId,state,reasonCode,result:null|TaskResult,reviewStatus:'pending'|'approved'|'rejected'|'unknown',selectionId:null|string,expiresAt,updatedAt}`; result visible only after verified approval, unexpired and authorized.
- `VerifiedContext`: `{userId,projectId,conversationId,dataClass:'synthetic'|'approved_cloud_text',placement:'cloud_control_review_allowed',policyVersion,admissionId,deadlineAt,jobCostCapUsd,dailyCostCapUsd}`; created only from server reads.
- `SelectionDecision`: immutable `{id,jobId,inputHash,projectId,profile:'local_assist_v1',policyVersion,candidateId,modelDigest,deploymentId,admissionId,evidenceHash,healthAt,validUntil,exclusions,totalExpectedCostUsd:number|null,costUncertainty:string[],fallback:'governed_openai'|'human'|'none'}`.
- `Claim`: `{jobId,attemptId,deviceId,claimId,fence:number,inputHash,selectionId,modelDigest,leaseUntil,expiresAt,task}`; server creates, worker cannot substitute binding fields.
- `ReviewReceipt`: `{jobId,attemptId,inputHash,resultHash,reviewRunId,reviewAttemptId,reviewerDeployment,status:'approved'|'rejected'|'unknown',reasonCodes:string[],usageRef,createdAt}`; produced from a persisted owned reviewer run, not accepted from local output.
- `TransitionResult<T>`: `{kind:'applied',value:T}|{kind:'duplicate',value:T}|{kind:'refused',reason:string}|{kind:'unknown',reconcileId:string}`. Database failure is not a successful CAS or proven absence.
- `WorkerEnvelope`: `{version:1,deviceId,buildHash,keyId,counter:string,nonce:string,issuedAt,expiresAt,method,path,bodySha256,signature}`; exact raw bytes hashed, decimal uint64 counter, UUID nonce, 60-second maximum validity, P-256/SHA-256 IEEE-P1363 signatures. Server persists counter/nonce atomically with accepted operation; body maximum 64 KiB.
- `Db` is the existing admin-client return type, never transported to the device. `Clock` is `()=>Date`. `TaskResult` comes from the shared strict schema.
