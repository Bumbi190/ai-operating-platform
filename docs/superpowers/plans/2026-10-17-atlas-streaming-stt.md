## Review Focus
1. Automatic provider segment commit during a long thought must not finish the user's question: Tasks 2/3 test internal segments and one final dispatch.
2. Connection starts too slowly to retain the first word: Task 4 tests 64,000-byte preflight bound, clear failure and no clipped submission.
3. Phone loses its socket after audio may have been billed: Task 3 tests retained full reservation and Task 4 tests no batch replay.
4. Stop/correction races with final text or session startup: Tasks 3/4 test late events and epoch suppression, including repeated start.
5. Tiny questions or an empty tail after a checkpoint must not hang or lose text: Tasks 2/3 test empty-tail finishing and Task 6 measures short questions separately.

## Protocol clarification discovered during planning
Official commit-strategy documentation states that manual mode can still auto-commit at about 36 s and processing begins after the first 2 s. A provider committed segment is therefore NOT necessarily a whole question. Preserve the spec's one user endpoint/one chat submission, with internal checkpoints every 20 s of forwarded audio so no segment reaches the automatic threshold. Allow exactly one checkpoint in flight; wait for its committed transcript before forwarding more, with the same 64,000-byte queue limit. An empty tail reuses the last acknowledged checkpoint instead of asking for an unobservable empty commit.
This specifies the segment-handling requirement already present in the spec. It does not shorten the user's pause or permit partial actions. Verify the protocol with a simulated provider and the later bounded provider probe; if completion cannot be distinguished reliably, keep the pilot off.
Source: https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/transcripts-and-commit-strategies
