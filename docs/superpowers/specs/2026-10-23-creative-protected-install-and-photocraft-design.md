## Protected path and ownership proposal

Use only existing fixed `C:\ProgramData\OmniraCreativeWorker` project root after a fresh independent elevated READ-ONLY audit. Candidate launcher destination, **not an existing observed path**: `C:\ProgramData\OmniraCreativeWorker\bin\launcher\SyntheticLauncher.exe`. Candidate approved receipt/manifest metadata is stored only in a separately reviewed trusted control/ledger location, not in worker-writable output. Protect every ancestor and leaf against reparse, junction, mountpoint, hardlink substitution, untrusted write, DELETE_CHILD, WRITE_DAC and WRITE_OWNER.

- `C:\ProgramData`: audit ancestor only; do not alter global ACLs.
- `OmniraCreativeWorker`: trusted owner SYSTEM/Administrators, no untrusted ability to replace controlled children; inspect explicit and inherited ACEs.
- `bin` and proposed `bin\launcher`: SYSTEM/Administrators write; worker read/execute only when separately authorized, never write/delete/ACL management. Exact before/after metadata and executable bytes recorded.
- `queue`, `input`, `receipts`: read-only for worker per existing provision policy; `output`, `temp`: worker narrowly Modify under its private project scope only. No worker path can replace `bin`, `control`, `approvals` or `nonces`.
- `approvals` and `approvals\nonces`: owner SYSTEM/Administrators, protected DACL, only those two principals' explicit full-control ACEs; worker receives no allow ACE. Never reset or delete existing contents. Distinguish earlier empty-tree audit from fresh inspection.
- `control` and `imports`, if used: owner SYSTEM/Administrators, protected DACL, no worker/user write and independently attested exact files before ANY elevated read of code/data. They must not be auto-created or trusted just because a path exists.

## Required separate acceptance sequence

1. **Non-elevated fixed-byte inventory.** Rehash every retained P42 packet entry and PhotoCraft original CLI and ZIP. Run read-only standalone P42 verifier. Record full 64-hex hashes, lengths, source commit, current P42 revision, and capture time. A verifier `packageConsistent=true` is not an approval.
2. **Independent Windows system-owned administrator read-only inspection.** A human must separately authorize a fresh console reading only owner, DACL, inheritance, reparse flags, directory type and exact entries for ProgramData/root/bin/queue/input/output/temp/receipts/approvals/nonces and any proposed control/imports directories. Use fixed trusted Windows binaries/modules from a fresh elevated console, **never an elevated script from this repo**. Match all ACE identities and allowed rights against the separately reviewed policy. Any unreadable, inconsistent, pre-existing target, unexpected reparse, untrusted writer, receipt or unknown member => STOP; do not repair by loosening ACLs. Store raw results privately.
3. **Independent authenticated approval anchor.** A distinct authorized operator reviews exact packet raw manifest SHA-256, host SHA-256, source revision, approved target path and operations plus expiry. Bind approval to a trusted protected receipt/nonce ledger with operator authentication, one-use consumption, persistent replay/revocation and crash-safe recovery. Such a channel and signing key custody are **not yet implemented/qualified**. No ephemeral UI click or sibling manifest.sha256 is an acceptable substitute.
4. **Design/review fixed protected-only bootstrap.** Code provenance and bytes are authenticated independently, sourced exclusively from a trusted protected root, not the developer checkout. A new reviewed copy-only installer must accept no arbitrary source executable, target, account or capability CLI selector; open approved packet through the same pinned non-inheritable source handles for hashing and copying with concurrent write/delete sharing denied; compare all four leaves, original raw manifest hash and host hash against the independently authenticated approval (not only the packet's sibling hash); create fixed protected target with final security descriptor **at create time**, fail on existing names, hardlinks/reparse or ownership drift, copy exact bytes without executing; flush and independently rehash protected destination under held handles, comparing directly to the authenticated approved digest as well as the source digest. Observe before/after ACLs and zero privilege grants.
5. **Rollback / non-cleanup.** Fail closed on any error; no blanket recursive deletion, no permissions reset, no forced take-ownership. Remove only exact new unchanged empty objects proven to be owned by this operation and permitted by a separately reviewed rollback; otherwise preserve partial evidence, all approvals/nonces/revocations and the disabled worker account. Report source, destination, authority and cleanup separately.
6. **Separate B0 qualification authorization, then B1 operational acceptance.** Installed synthetic P40 host is not a PhotoCraft runner. Before actual-worker behavior can be *demonstrated*, independently approve a **one-time bounded inert diagnostic** after checkpoint A: exact protected synthetic binary, fixed synthetic fixture only, audited temporary account enablement if technically required, fixed time/process/job/network scope, positive controls, independent observer, disabled-state readback and cleanup evidence. No general creative editor, external assets, production broker or privileged worktree execution. Failure to return the account to disabled or to verify cleanup blocks further steps. B0 diagnostic authorization does NOT grant ongoing worker/PhotoCraft execution. Only after this controlled diagnostic, evaluate actual `omnira-media-worker` token (not an ordinary AppContainer token), job descendants, file isolation from other projects/credentials, installed Node/helper provenance and effective network-denial matrix (DNS, TCP/UDP, IPv4/IPv6, LAN/loopback/proxy, helper and broker paths). Also validate the registered worker public-key identity and authenticated claim-path integration against an isolated staging DB, including durable protected operator approval, expiry, one-use consumption and replay/revocation checks. These backend controls are distinct from the B0 inert diagnostic. Any incomplete B1 evidence blocks a real creative job; the account remains disabled between explicitly approved sessions.

Review and separately approve a fixed PhotoCraft-only protected ZIP extraction/Authenticode/hash stage plus a narrow `photocraft.convert-webp` adapter.
