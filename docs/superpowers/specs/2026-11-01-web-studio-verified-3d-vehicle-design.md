# Web Studio Verified 3D Vehicle — Design

## Intent
Add a real free-camera 3D vehicle view to premium dealer websites without ever implying that a fictional or approximate model is the customer's exact real car.

## Current baseline
- Demo Motors already has a verified 12-frame `spin` behavior for the first fictional concept car.
- That feature is a 360-degree image sequence, not free 3D and not a digital twin.
- Its provenance truth class is `fictional_concept`.
- The static website artifact is self-contained HTML/CSS/runtime with a 1 MiB artifact limit. Binary 3D assets therefore must stay outside model-generated HTML payloads.

## Truth classes
### fictional_concept
Used for Demo Motors and other invented showcase vehicles.
- May use Blender/AI-assisted modeling.
- Must be labelled concept/demo.
- Must never claim exact real-world vehicle identity.

### real_vehicle_verified
Used only when the 3D asset is tied to a specific real vehicle/configuration.
Required evidence:
- make, model, model year and trim;
- exterior color;
- wheel design/size where visible;
- source provenance for the mesh/model;
- at least four reference views covering front 3/4, side, rear 3/4 and opposite side/front;
- human approval of fixed-angle comparison renders.
If any required evidence is missing, the asset cannot receive this truth class.

## Same-source visual rule
For any 3D-enabled hero/vehicle card, the displayed 2D poster and the free 3D viewer must derive from the same approved 3D asset whenever the page claims visual identity continuity.
- Demo: re-render the poster/hero from the same Blender/GLB source used by the 3D viewer.
- Real vehicle: use a poster rendered from the exact verified GLB, or a real reference photo explicitly bound to the same vehicle configuration.
- An independently generated AI hero image cannot be used as proof that a verified 3D model matches reality.

## Runtime format and renderer
- Delivery format: GLB / glTF 2.0.
- Renderer: Three.js pinned to 0.187.0.
- Loader: `GLTFLoader` from the Three.js addon package.
- No CDN/runtime third-party network dependency; all viewer code is bundled/self-hosted.
- GLB is a governed binary asset, not text/base64 generated by the model.
- Keep existing 360 spin as a fallback when WebGL/3D initialization fails or the asset is unavailable.

## Viewer interaction
- Orbit around vehicle.
- Bounded zoom.
- No camera entry through the mesh.
- Pointer/touch and keyboard-accessible controls.
- Reduced-motion mode disables decorative auto-motion.
- Loading state and explicit fallback to 360/poster.

## Asset architecture
A governed `Vehicle3DAssetManifest` binds:
- asset id;
- truth class;
- GLB SHA-256;
- poster SHA-256;
- source type (Blender concept, licensed CAD/OEM, photogrammetry, verified vendor model);
- vehicle identity/configuration fields when real;
- evidence references;
- approval state.
Website model output may reference only an approved asset id.

GLB bytes live as a separate built-in/export/storage asset. They are not counted as model prompt bytes and are not embedded inside the 1 MiB static artifact JSON/HTML contract. Static export copies the approved binary to a relative `assets/3d/` path.

## Demo Motors V1
Use the existing fictional Blender source that produced the 12-angle proof, export a GLB from that same source, and render a matching poster from it. This proves the free-camera pipeline for $0 model/media spend.
The page must continue to state that the vehicle is fictional.

## Real dealer V2
Accept only an evidence-backed source: photogrammetry/360 capture converted to mesh, licensed OEM/CAD source, or a vetted model that can be proven to match the exact configuration.
AI may assist cleanup/material work, but AI-only inferred geometry must not receive `real_vehicle_verified`.

## QA gate
Before a real vehicle can be published:
1. validate GLB format and SHA;
2. render fixed camera views;
3. compare them with the bound real reference views;
4. verify visible configuration details;
5. human reviewer records approval;
6. only then expose the real-vehicle truth label.

## Budget boundary
The existing Demo Motors Blender source should be reused first, so V1 can be developed without consuming the approved $10 AI/media allowance.
Any paid scanning/model-generation/vendor asset purchase is a new cost decision and must be approved separately.

## Optional Higgsfield production lane
Higgsfield is an optional production tool, never the website runtime or truth authority.
- Available 3D models include SAM 3 image-to-GLB, Meshy single/multi-image-to-GLB and Hunyuan3D multi-view GLB generation.
- Prefer the existing exact Blender/GLB source when one exists; reconstructing an already-known model from images is a downgrade risk.
- Use multi-image reconstruction when no trustworthy 3D source exists and multiple views of the same subject are available.
- Higgsfield-generated geometry is `ai_inferred` until independently verified; it cannot become `real_vehicle_verified` merely because it looks plausible.
- 3D Jutsu may be used for scene composition, inspection, lighting, camera work and GLB iteration while Omnira/Three.js remains the delivery runtime.
- Any paid 3D generation is preflight-priced and requires the existing cost approval boundary before submission.
